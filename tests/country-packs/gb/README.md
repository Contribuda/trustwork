# CTRY-GB source review and acceptance

The United Kingdom pack is configuration data. It has no live register, tax, payment or signing adapter, no country-specific engine branch and no EU layer inheritance. Source access dates use UTC: 2026-11-01. English uses `en` with `en-GB` formats; Welsh is a contributor-language lead, not an installed locale.

## Focused verification

Run the country-pack test tree with one test worker, then the repository typecheck, eslint on changed TypeScript files and `npm run validate:docs`. The conductor's LOAD RULE delegates the full gate and browser suites to CI. Tests exercise nation inheritance, exceptions, holiday collisions, format handling, UTR exclusion, provenance, rejected tampering and absence of GB engine branches.

## Follow-ups and scope

- Reconcile the CLDR snapshot with the current ISO register; add current local-authority mappings separately instead of treating historical ISO areas as permitting authorities.
- Review special Companies House formats, VAT branch and XI identifiers, Northern Ireland gas/trade rules, construction contract exclusions and current statutory amendments.
- Counsel must approve jurisdiction settings and storage/transfer decisions. Candidate adapters need access terms, fakes and authorization tests before activation.
- Refresh official holiday dates beyond 2028 and after any newly announced day; support local calendars separately.
- Registering GB requires the shared server registry, the country dataset pack flag and its generator, and the generated v1 client projection. The common pack-list assertion changes only to include GB; status/chapter and CTRY-GB's work-package entry record the delivered pack. These minimal integration/hand-back files are outside the package's two primary paths.
