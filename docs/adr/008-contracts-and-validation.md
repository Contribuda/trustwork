# ADR 008 — Contracts, validation, digests and API conventions

Date: 2026-10-27. Status: **accepted by integrator 2026-10-27** (FND-002 freeze of the reviewed BE-000, RAG-101 and ADM-000 research). Human product decisions listed under "Open" remain open.

## Context

Backend (DATA-001, BE-001, COM-001, BILL-001, CNT-001, ADM-001), retrieval (RAG-201, RAG-301) and web lanes must start in parallel from one validated vocabulary. `packages/contracts` previously held hand-written TypeScript types without runtime validation; the research proposed Zod, a canonical digest and an error/idempotency convention (technology recommendations (private repository record, not exported), immutable commercial contracts (private repository record, not exported), contract questions Q01–Q09 (private repository record, not exported)).

## Decisions

1. **Zod 4 (`zod@4.6.7`, exact) is the contract language.** Every command, query, aggregate and read model in `packages/contracts/src` is a Zod schema with its inferred type exported beside it. Objects are `strictObject`, so unknown fields are rejected and mass assignment is impossible by construction. The package is plain ESM consumed by Nest (through `nestjs-zod` pipes, added by BE-001) and by Next. JSON Schema (draft 2020-12) is generated with `z.toJSONSchema` from the same source (`contractJsonSchemas()`); OpenAPI is derived from it, never hand-maintained. Typed SQL adapter for DATA-001: **Kysely + `pg`** (query builder, not an ORM; migrations stay plain reviewed SQL). DATA-001 added `kysely@0.29.7` and `pg@8.23.1` (exact) to `@trustwork/data` with integrator agreement.
2. **Digest `trustwork-digest-1` = lowercase hex SHA-256 over RFC 8785 (JCS) canonical bytes of an explicit `digestInput`.** JCS is implemented in pure TypeScript in `common/canonical.ts` (UTF-16 code-unit key order, `JSON.stringify` escaping, I-JSON finite numbers, no whitespace, no Unicode normalization) and tested with the RFC 8785 vectors. NFC normalization happens at input validation (Zod `overwrite`), so stored and digested bytes are identical. Money and quantities are strings; `VersionRef.version` is the only JSON number inside digest inputs. Digest inputs: RFQ version `{ payload }`; quote version `{ rfqVersion, payload }`; agreement `{ quoteVersion, rfqVersion }` computed once at creation (acceptance events reference it and are never digest input). The server computes digests; client-supplied digests are compared and rejected (`commercial.digest_mismatch`). Pin by id, verify by digest: staleness, comparability and acceptance use `VersionRef.id`.
3. **Immutability and staleness.** Published RFQ versions and sent quote versions are immutable (`reject_update_when_frozen` covers `payload`, `digest`, `rfq_version_id`, `rfq_version_digest`, `valid_until`, `sent_at`, `sent_by`, `published_at`, `published_by`; `quote_version.valid_until` mirrors the frozen `payload.validity.until` and acceptance reads expiry from the payload); drafts are edited with `expectedRevision`. Acceptance (`checkAcceptance`) re-verifies the stored quote and RFQ payloads against their recorded digests before comparing the supplied `VersionRef` (id, version and digest). Invitations and quote versions pin `rfq_version_id`. Staleness is `rfq_version_id !== current_rfq_version_id`, expressed as `staleReason` on top of an unchanged status (no `stale` status). A v3 that restores the v1 payload has the same digest but a new id, so v1 responses stay stale.
4. **Money and quantity.** `{ minorUnits: string /^-?(0|[1-9]\d*)$/, currency: ISO 4217 }`, `{ value: decimal string (≤ 6 fractional digits), unit: catalogue code }`. Arithmetic helpers refuse mixed currencies and units; conversion requires an explicit `ExchangeRateSnapshot` and rounds half-even.
5. **Ownership and parties.** `Party = { kind: 'person' | 'company', id }` (XOR). Creator, owner and leader are distinct. One active employer membership. Capability vocabulary (15 values) and the five projection layers `public`, `shared_party`, `party_private`, `owner_private`, `staff_case`; grant audience `shared_party | party_private | owner_private`.
6. **API conventions.** Single origin, `/v1/*`. Error envelope `{ code, message, details?, requestId }` with English machine codes in the namespaces `auth.*`, `access.*`, `commercial.*`, `membership.*`, `validation.*` and a fixed HTTP status per code; the web maps codes to `ru.error.<code>`. Disclosure: `access.not_found` unless existence is already known to the principal, then `access.forbidden`. `Idempotency-Key` scoped `(principal, action, context, key)` with payload digest; `expectedRevision` on versioned edits. External outcomes are `unknown | acknowledged | final`; crash reconciliation is a separate `Reconciliation` record and the only path from `unknown` to `final`.
7. **Retrieval, billing, content and administration vocabularies** are frozen in `retrieval.ts`, `billing.ts`, `content.ts` and `admin.ts` to the extent downstream briefs need them (RAG-101 `EmbeddingConfig`/`IndexGeneration`, two budget kinds and price versions, publication/issue/correction shapes, `admin.<domain>.<action>` permissions, `AdminAuditEvent`, `CaseAccessGrant`, second-person approvals bound to an action digest).

## Deviations from the research (with reasons)

- Grant audience `shared` is named `shared_party` to match the projection layer name used by the integrator decision; `read.shared` stays as the capability name.
- Identifiers are opaque bounded tokens rather than a UUID format constraint: persistence generates UUIDs, fixtures stay readable and the storage choice does not leak into clients.
- `QuoteLine` carries `taxAmount` so totals can be recomputed exactly from stored lines without a rounding policy inside contracts; rounding of unit price × quantity remains the seller's responsibility and the comparison layer's concern.
- `RetrievalResult`/`EmbeddingConfig.metric` is an enum (`cosine | inner_product | l2`) as RAG-101 proposed; approved configs with `cosine` must declare `normalization: unit`.
- `compatibleVector` accepts a minimal `{ configId, generationId, values }` record so existing fixtures and future callers do not need the persisted `inputKind` for the representation guard.
- Agreement party-private data is split into separate records (`AgreementBuyerPrivate`: budget and approval references; `AgreementSellerPrivate`: fulfilment plan) with `toBuyerAgreement` / `toSellerAgreement` serializers, mirroring the RFQ and quote private-constraint pattern, so no party can see the other side's internals.
- Participants see shared milestones without budgets (`SharedMilestone`).
- A `tainted` index generation can only retire; the two-step `tainted -> draining -> active` path is closed.
- `z.toJSONSchema` drops `refine` checks (digest equality, actor != approver, 72-hour expiry, totals recomputation and similar invariants). Generated JSON Schema / OpenAPI describes shapes only; consumers must not treat it as the full invariant set, which lives in the Zod schemas and the pure guards.

## Consequences

- `apps/api` and `apps/worker` keep importing `health` and `evaluateDelegation` from the server barrel (`.`). The package exposes two entries: `@trustwork/contracts` (server: adds `computeDigest`/`verifyDigest` on `node:crypto` and the server-only commercial guards in `server/commercial.ts` — digest computation, `AgreementSchema`/`AcceptanceEventSchema` with digest refinements, `checkAcceptance`) and `@trustwork/contracts/client` (schemas, types and pure guards only; no `node:` import, no `Buffer`, no digest computation reachable — enforced by a static import-graph test and an esbuild `--platform=browser` bundle test). Clients receive digests from the server and only compare them (`digestEquals`).
- DATA-001 requests from these contracts: `UNIQUE (rfq_id, version)`, `UNIQUE (quote_id, version)`, `reject_update_when_frozen` triggers, FK/trigger that a quote pins a published current RFQ version at send time, digest equality triggers for acceptance events and agreements, `bigint` money with `char(3)` currency, `numeric(18,6)` quantities, identity tables `email_binding.is_primary`, `auth_token`, `login_failure`, `person_authz_epoch`, `company_authz_epoch`.
- Reconsideration triggers: measured validation overhead on hot endpoints, a second public origin, a required change to the digest algorithm (new name, never a silent re-hash), or an accepted product decision that changes a frozen enum.

## Open (human decisions, not blocking)

Password minimum length (contract default 15, parametrized by `PasswordPolicy`), session lifetimes, lockout thresholds, recovery hold for corporate mailboxes, audit retention, residual read-only access for former employees (contract questions H01–H11 (private repository record, not exported)), measurement-unit catalogue (O11) before `unit` validation can be strict, electronic-agreement requirements (O12).
