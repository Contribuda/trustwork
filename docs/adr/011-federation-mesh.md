# ADR 011 — Federation: the Trustwork mesh

Date: 2026-10-30. Status: **proposed by the integrator 2026-10-30** for owner decision 7 of [ADR 010](010-gathering-point-hubs-agents-and-mesh.md). Not implemented. The full design is the handbook chapter [Federation and the mesh](../engine/federation.md); this record fixes the architectural choices that later tasks must not silently change.

## Context

The owner wants every deployment of the engine to be able to join one network: a country hub and a separately operated city hub inside that country complement each other, and all deployments together form a mesh covering the world. Today every deployment is an island: one PostgreSQL database, one origin, identifiers that mean nothing outside it.

Constraints carried over from earlier decisions: projections are explicit allowlists (R28, ADR 008); accepted commercial terms are bound by `trustwork-digest-1` (ADR 003); payment never buys ranking (R14); sourced, claimed and verified stay distinct (R15); untrusted content never authorizes actions; nothing is served to, hosted in or routed through restricted places (ADR 009).

## Decision

1. **Nodes and hubs.** A *node* is one independently operated installation of the engine (its own database, origin and operator). A node hosts one or more *hubs*. A hub has a *territory*: one country, or one or more ISO 3166-2 subdivisions, or one or more cities (a city is a named place with a stable identifier, see the handbook). Territories may overlap; a territory claim is descriptive, never exclusive.
2. **Node identity.** Each node has a DNS name and an Ed25519 signing key published in a signed manifest at `https://<node>/.well-known/trustwork/manifest.json`: protocol versions, engine version, hubs and territories, languages, country pack versions, operator legal entity and jurisdiction, contact for abuse and takedown, data licence per data class, accepted federation policies, key rotation history. Key rotation is signed by the previous key.
3. **Global identifiers.** Every federated object has a global identifier `trustwork://<node-host>/<kind>/<local-id>`. Local opaque IDs stay as they are (ADR 008); the global form is derived, never parsed for authorization. The node that created an object is its **home node**, the only writer. Every other node holds a read-only **replica** with provenance.
4. **Protocol.** HTTPS with JSON documents, signed with HTTP Message Signatures (RFC 9421) using the node key. Each object travels as a signed envelope `{ id, kind, revision, homeNode, projection: "public" | "shared_party", payload, digest, issuedAt, signature }`, where `digest` is `trustwork-digest-1` over the canonical payload (the same JCS scheme as commercial versions). Nodes exchange data by **pull** (cursor feeds `GET /federation/v1/feeds/<stream>?after=<cursor>`) and **push** (inbox `POST /federation/v1/inbox` for deliveries, deal messages and tombstones). Pull is the default; push only for objects addressed to a specific party.
5. **What federates.** By default only the `public` projection: published publications and their corrections, released magazine issues, public events, public profiles of people (only with `profileVisibility: public`) and companies, public projects and open needs, public catalogue fields, reputation snapshots with their method version. `shared_party` data travels only for a cross-node deal, only between the home nodes of the parties, only for objects both parties participate in. `party_private`, `owner_private` and `staff_case` never leave the node.
6. **Peering, not a central server.** Nodes federate through bilateral **peering agreements** recorded on both sides with a level: `syndicate` (pull public feeds), `trust-verifications` (display the peer's verification badges with attribution), `deal-routing` (accept cross-node commercial messages) and `identity` (accept sign-in assertions). A node can defederate at any time; defederation stops feeds and new deals, never rewrites history. A community-run **mesh directory** may list nodes that ask to be listed; it is discovery only, not authority.
7. **Entity linking, never merging.** When two nodes know the same company (same registration identifier kind and value from the same country pack) or the same person (a signed link from the person), they record a **link** between the global identifiers. The record with the strongest claim status is the canonical display; the others keep their provenance. No automatic merge, no silent overwrite (consistent with the directory rule of the administration design).
8. **Authority stays home.** Reputation is computed only by the home node of the subject, under its published method version; replicas display it with the method link and the node name. Verification badges carry the node and the evidence categories that granted them; a node shows a peer's badge only at `trust-verifications` level and labels it as granted elsewhere. Moderation decisions are local: a node may hide a replica, but cannot change the home object.
9. **Deals across nodes.** A participant on node A may invite a participant on node B to an RFQ, send an introduction or negotiate. The RFQ version, quote versions and agreement are created on the home node of their author and replicated as `shared_party` envelopes to the other party's node. Both nodes verify the digests; acceptance binds the same `trustwork-digest-1` value on both sides, so each party holds provably identical terms. Mandates, budgets and approvals stay on each party's own node; nothing on node B can authorize an action on node A.
10. **Agents across nodes.** Agent messages between nodes are deliveries to the counterparty's inbox, labelled as agent-generated, rate-limited per peering and treated as untrusted content by the receiving node and agent.
11. **Corrections, erasure and takedown propagate.** A correction is a new revision; a deletion or erasure is a signed tombstone that peers must apply within the period stated in the peering agreement. A node that fails to honour tombstones is defederated.
12. **Sanctions and law.** A node whose manifest declares a restricted place as its jurisdiction or territory is refused at handshake; peers screen operator entities like partners (ADR 009). Cross-node deals run each node's own screening on the counterparty before the first commercial message. Each node remains responsible for its own legal compliance; peering never transfers that responsibility.
13. **Licences of data.** Each data class in the manifest states the licence under which peers may store and redisplay it (for example editorial content "redisplay with attribution and link", public directory facts "open data"). Source-licensed items (news imported from a source whose licence covers only the home node) are marked `syndication: none` and do not leave the node. Default licences per data class were decided by the integrator on 2026-10-30 under the owner's delegation ([ADR 010](010-gathering-point-hubs-agents-and-mesh.md) decision 10; table in the [federation chapter](../engine/federation.md#data-licences)); nodes may only make them stricter.

## Alternatives considered

- **One global central database.** Simplest search, but contradicts independent operators, data residency (UZ requires local storage of citizens' personal data, ADR 009 pack facts) and the AGPL premise that anyone may run the engine. Rejected.
- **ActivityPub as is.** Mature for social posts and widely deployed; its object model and inbox semantics fit publications and events well. It does not cover digest-bound commercial versions, projection levels or signed manifests with territories. The mesh protocol borrows its inbox/outbox shape and may offer an ActivityPub bridge for publications later; it is not the core protocol.
- **Blockchain or a distributed ledger.** Adds cost and governance without solving the hard parts (legal accountability, takedown, privacy). Digests plus signatures give the integrity we need. Rejected.
- **Peer-to-peer replication of everything.** Violates projections and residency. Rejected.

## Consequences

- New module `federation` (node identity, manifest, peering, feeds, inbox, replicas, links, tombstones) and a `replica` storage class with provenance; replicas never satisfy an authorization check for writes.
- Global identifiers and signed envelopes become part of the contracts (`packages/contracts/src/federation.ts`, future).
- Search and retrieval index replicas under their own source class and licence flags; private retrieval never reads replicas of `shared_party` data except for parties of that deal.
- Work packages FED-000…FED-005 in the task graph; FED-000 freezes the protocol before any implementation.
- Reconsideration triggers: an accepted external standard that covers digest-bound commercial objects, measured feed lag or volume beyond what pull with cursors can handle, or a legal finding that changes what may federate.
