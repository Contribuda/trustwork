# ADR 009 — International engine, country packs, sanctions and open-source readiness

Date: 2026-10-29. Status: **owner decision, recorded by the integrator 2026-10-29** (owner's task hand-over of 2026-10-29, author Dmitry Parshkov, repository owner). These decisions override earlier constraints wherever they conflict (precedence of the operating agreement: explicit current human decisions first).

## Owner decisions (2026-10-29)

1. **International product with a country selector.** Launch markets: Uzbekistan (first, complete), Georgia, Armenia, Azerbaijan. Each country has its own language(s) and currency.
2. **Russia is not a market.** Russia, Crimea, Sevastopol, the Donetsk and Luhansk regions of Ukraine, Cuba, Iran and North Korea are blocked under US sanctions (the owner is a US person; the hosting platform applies the same rule to the preview). None appears in the country selector; nothing is built, hosted, supported or handed over for a person or company located there.
3. **The UI is multilingual.** Supersedes the 2026-10-26 rule "all product UI copy is Russian". English is the engine's default and fallback language; Russian is one optional secondary locale.
4. **Open-source engine, prepared but not published.** Anyone may run their own reputation platform for their own country. Only the owner changes repository visibility or creates the public repository.
5. **The name and the logo lettering are localized** (superseded on 2026-10-31 by [ADR 010](010-gathering-point-hubs-agents-and-mesh.md) decision 14: Trustwork in every language, «Строй Репутация» only in the Russian interface) (owner, 2026-10-29, during INTL-002 review): in every language the brand reads "build reputation". The mark (three blue squares) is shared; the stacked wordmark is outlined per language from the same generator: ru «строй / репутация», en "build / reputation", uz-Latn "obroʻ / qur", ka "ააშენე / რეპუტაცია", hy "կառուցիր / համբավ", az-Latn "nüfuz / qur". Supersedes the "black stacked Russian lettering" wording of R25 and the operating agreement; the geometry and colours are unchanged. Georgian and Armenian lines use Noto Sans Bold because Golos Text has no glyphs for those scripts.
6. **The engine is named Trustwork** (owner, 2026-10-29, closes O18). The core team's GitHub repository is `Parshkov/trustwork` (old URLs redirect; it stays private); the public engine repository is `Contribuddha/trustwork` (owner decision of 2026-10-30, ADR 010 decision 12), packages are `@trustwork/*`, environment variables `TRUSTWORK_*`, cookies `trustwork.country` / `trustwork.locale`, CSS utilities `trustwork-*`, the digest algorithm label `trustwork-digest-1` (the value is unchanged: SHA-256 over canonical bytes), and the PostgreSQL schema and roles `trustwork`, `trustwork_app`, `trustwork_owner`, `trustwork_api` (migrations rewritten in place with the owner's explicit permission: no database has been populated). Deployment identifiers of the reference brand (the hosting platform service, `/trustwork` path) stay.

7. **Any country with any language** (owner, 2026-10-29). The visitor chooses any country that is not a restricted place and, independently, any engine language. Countries with a contributed pack (UZ, GE, AM, AZ) are offered first and bring regions, identifier formats, legal facts and a suggested language; every other country gets a generic profile from the ISO dataset in `packages/country-packs/countries` (currency, calling code, time zone, names; no regions, free-form registration number) until someone contributes its pack. The engine languages are the dictionaries that exist (en, ru, uz-Latn, ka, hy, az-Latn today); partial ones fall back to English.

8. **Licence: AGPL-3.0-only** (owner, 2026-10-29, closes O17). Hosted forks must publish their modifications; the brand assets of the reference deployment are excluded from the licence (`NOTICE`).

9. **Publication blockers closed** (owner list of 2026-10-29): the engine ships no photographs (the earlier third-party photo set was not open-licensed for a competing service and three portraits showed real people on synthetic profiles; covers come from the in-repo artworks, avatars are initials, a deployment registers its own licensed photographs); the design system letters the neutral Trustwork lockup and strings while the reference deployment's localized brand is an overlay in `apps/web/brand` that the export replaces with a stub; the export excludes the task graph, agent coordination files, evidence, operations, research, integrations and deployment infrastructure, swaps in the operator README and keeps the full check green on the exported tree; the merged backend's second sign-in provider is Sign in with Apple; `main` was merged into the conductor branch so one branch carries frontend and backend.

10. **Everything follows the chosen language, content included** (owner, 2026-10-29, after reviewing the preview in English: the magazine cover, article and news bodies and image captions were still Russian). Every visible string, including demo content, image captions, calendar and date labels and the brand lockup on magazine covers, renders in the active language. Demo content resolves per string: the locale's own override, then the English layer, then the base text; English must cover every base string (`tests/web/fixtures.test.ts`), so no Russian reaches a reader outside the Russian locale. Dates, months, weekdays, time zones and file sizes come from `Intl` for the active locale, never from hard-coded word lists. Translations of demo content into Uzbek, Georgian, Armenian and Azerbaijani are produced by the integrator and remain subject to native-speaker review.

## Engineering decisions (integrator)

1. **Engine plus country packs.** A pack is data and configuration in `packages/country-packs/packs/<cc>.json`, validated by a Zod schema and a test: locales and default locale, currency and formats, company registration identifier (label, pattern, validation), legal entity types, ISO 3166-2 regions, address format, legal-text template identifiers, data-residency requirement. Packs ship for `UZ` (complete), `GE`, `AM`, `AZ`. A `restricted` list (ISO 3166-1 alpha-2 and ISO 3166-2 codes) carries the sanctioned places; a restricted code can never be enabled.
2. **Registration identifiers replace ИНН/ОГРН.** Contracts keep a generic `legalIdentifiers[] { kind, value, status }`; the `kind` is a pack identifier code (`UZ-STIR`, `GE-IDC`, `AM-TIN`, `AZ-VOEN`), the label and validation come from the pack. Facts recorded in each pack cite their source; official confirmation is pending where only secondary sources were found (see pack `sources`).
3. **Currency comes from the pack.** No hard-coded currency; money is formatted with `Intl.NumberFormat` in the active locale and the pack currency (`UZS`, `GEL`, `AMD`, `AZN`); USD may be shown alongside. Minor units stay in the contracts (`Money.minorUnits`).
4. **Locale resolution.** Locales are the enabled packs' locales plus `en` and `ru`. The active country and locale are kept in cookies (`trustwork.country`, `trustwork.locale`), set from the first-visit selector, the header switcher, or `?country=`/`?lang=` on any URL (so links can carry them). On the server the locale is request-scoped (React `cache`) and primed by the root layout and every page; client components receive the locale and messages from a provider. Dictionaries: `packages/ui/locales/<locale>.json` and `apps/web/app/_lib/locales/<locale>.json`; `en` is the reference key set, every other locale falls back to `en` per key. Missing keys are reported by a test, never shipped as empty strings. RTL is out of scope.
5. **Fixtures are a country's demo data.** The demo dataset moves to Uzbekistan (regions `UZ-*`, STIR identifiers, UZS amounts, Uzbek Latin names). User-facing fixture strings become localized values (`{ "uz-Latn": …, "en": …, "ru": … }`) resolved by the active locale with the same fallback chain. Data stays synthetic and labelled.
6. **Russian integrations and plans are removed** from code, docs, briefs and research plans: accounting, e-document and public-procurement feeds, model APIs, identity and maps providers, the social share, CRM defaults, the data-localization law reference and the ruble entity. Russian state banks on OFAC's SDN list are never integrated. Auth providers sit behind a neutral adapter (`google`, `apple`, `microsoft`, email); Telegram share and OpenStreetMap stay.
7. **Sanctions in the product.** The operator terms template gains a "Sanctions and export controls" section mirroring the hosting platform's terms (section on sanctions and export controls) (restricted regions, listed persons, no transit/resale/indirect use, no VPN circumvention, user representations). Partner and reseller onboarding carries an ownership declaration and an SDN screening hook against the Consolidated Screening List (adapter with an empty key until the owner provides one). The hosted preview is reached only over the hosting platform's private network behind the landing's place check; no public domain or other way in is ever added.
8. **Data residency** is a pack field (`dataResidency: { required, note }`). Storage design keeps per-pack local storage possible. Local-law compliance is for local counsel and is not claimed in docs.
9. **Payments** stay adapters only; no Russian payment rails; Stripe availability per country is not assumed.
10. **Open-source readiness** (prepare only): a scripted export into a fresh repository with no history; gitleaks plus a manual personal-data pass; `LICENSE` (AGPL-3.0-only, decision 8) and `NOTICE` with an export-control notice; community files (README for operators, CONTRIBUTING with DCO, CODE_OF_CONDUCT, SECURITY, templates, governance note with the "contributors in restricted places: pending counsel" flag); a "how to add your country" guide and the pack validator; brand separation (the engine is Trustwork, decision 6; "Строй Репутация" is one deployment).

## Open (owner)

- O17 and O18 are decided (decisions 6 and 8 above).
- O19 When and how to publish the exported repository.

## Consequences

- `packages/ui/locales/ru.json` stops being the contract for UI copy; `en` is. Tests that asserted "Russian copy only" become "no untranslated keys in the active locale".
- `RegionKey` is no longer an enum of Russian regions; it is an ISO 3166-2 code validated against the active pack.
- Deployment constraints are unchanged: `basePath` `/trustwork`, port 3000, private network only, no deployment without the owner's authorization.
