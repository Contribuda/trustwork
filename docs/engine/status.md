# What works today, and what is designed

We would rather under-promise. The normative requirements of every module, with a status per requirement, are in the [module specifications](modules/README.md). This page says, area by area, what you can run today, what exists only as a demo on synthetic data, what is frozen as a contract, what is designed, and what this handbook proposes for the first time. It is updated whenever a work package is accepted.

LLM-001 remains partial and blocked on mandatory governance integration: its fake-only gateway uses real KEYS routing, durable BILL effect holds, locked mandate accounting, cross-process dispatch ownership and an AST commit/finalization boundary. The default application model remains unavailable; AGT-003 authority is not fabricated. See the [integration boundary and bounded evidence](../../apps/api/src/modules/models/README.md); no model gateway is claimed Live.
**Proposed design review material:** [administrative interface guidelines](../design/admin-ui-guidelines.md), [Proposed ADR 019](../adr/019-admin-ui-libraries.md) and [six localized offline prototypes](../design/prototypes/README.md). These synthetic interaction studies do not add application routes or change the live/demo/contract status below; implementation package publication awaits the owner's package-ID decision.

## Status levels

| Level | Meaning |
|---|---|
| **Live** | Implemented end to end on PostgreSQL with automated tests, including negative authorization tests. Not yet deployed to production anywhere. |
| **Demo** | The user interface exists and is tested in a browser, but it runs on synthetic demo data (`apps/web/fixtures`). Nothing is stored; buttons that would act externally are imitations and say so. |
| **Contract** | The data shapes, state machines and invariants are frozen as Zod schemas in `packages/contracts` with tests. No storage or API yet. |
| **Designed** | An accepted design document or ADR describes it; no code yet. |
| **Proposed** | Designed in this handbook for the first time (owner decisions of 2026-10-30 and 2026-10-31). Open for review and discussion. Each proposed area has work packages in the [roadmap](roadmap.md). |

## What this means if you try it

- Public pages have one address per language (WEB-005, ADR 012 decision 27): English without a prefix (`/news`), every other language under its prefix (`/ru/news`), with canonical and `hreflang` links. Every page is rendered per request with the strict nonce policy; full-page caching of public pages is deferred until a no-inline-script or build-time hash approach is proven. Public pages never read the session on the server (their visitor-specific parts load in the browser), and mobile Web Vitals budgets run in CI.
- `TRUSTWORK_DEMO_MODE=1 npm run dev:web` shows the whole public site and workspace on synthetic data in seven languages: with `TRUSTWORK_DEFAULT_COUNTRY=US` (the hosted preview) the San Diego demo hub, otherwise the original Uzbekistan example, which also serves visitors who choose Uzbekistan, Georgia, Armenia or Azerbaijan (DEMO-US). Personas are chosen with `?persona=reader|mixed|owner|seller|buyer`, only in demo mode.
- `npm run dev:api` with the local database and the restricted runtime role printed by `npm run seed:dev -w @trustwork/api` runs the live identity, company and project API under `/v1/*` ([agent onboarding](agent-onboarding.md#3-install-and-run) has the exact commands).
- The API process has a production runtime baseline (OPS-001): it refuses to start with `NODE_ENV=production` without `AUTH_FLOW_SECRET`, an `https` `PUBLIC_ORIGIN` and secure cookies; writes one redacted JSON log line per request; answers `GET /health/live` and `GET /health/ready` (database and migration ledger); exports OpenTelemetry-compatible traces and metrics only when `OTEL_EXPORTER_OTLP_ENDPOINT` is set; and sends security headers. Every web page, public ones included, carries a per-request nonce-based Content Security Policy. Nothing is deployed to production.
