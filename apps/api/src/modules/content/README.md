# Content module: publications, corrections and curated issues (CNT-001)

The sourced publication lifecycle and the weekly curated issue ([News, articles and walls](../../../../../docs/engine/publishing.md), [The weekly magazine](../../../../../docs/engine/magazine.md), [data model sections 10 and 11](../../../../../docs/data/model.md#10-content)). Contracts: the frozen [`content.ts`](../../../../../packages/contracts/src/content.ts) (`PublicationSchema`, `PublicationVersionSchema`, `IssueSchema`, `CorrectionSchema`, both transition tables) reused unchanged; request and view schemas the contracts do not carry are in [`schemas.ts`](schemas.ts). Storage: [`packages/data/migrations/content`](../../../../../packages/data/migrations/content), [`packages/data/src/repositories/content.ts`](../../../../../packages/data/src/repositories/content.ts).

Status: **Live** as an API with the CNT-003 web reader and opt-in local PDF worker; acceptance remains incomplete for editorial provenance and manual accessibility review. Tests: `tests/content/*` and `tests/backend/idempotency/cases/content.ts`, on real PostgreSQL under the runtime role.

## Rules the database enforces

- **One store, three owners.** A publication is owned by a person, a company (members holding `company.publish`) or the hub's editorial office (staff holding `admin.publications.*` at the hub, through an elevated session). Format fixes the owner where it must: `personal_post` a person, `company_post` a company, `magazine_piece` the editorial office.
- **Credit is not a right.** `publication_authorship` (credits, frozen at the first publication) and `publication_editor` (`edit` drafts; `publish` also publishes, corrects and retracts; granted by the owner party, never to oneself; revoked, never deleted) are separate tables. A credited co-author cannot edit; an editor is never credited. The model's earlier wish to express editing rights as participation rows is not used: `owns_resource`/`can_manage_resource` do not know publications, and changing those foundation functions is outside this package (see "Deviations").
- **Immutable versions.** A version is frozen once published (`reject_update_when_frozen`, every role including maintenance; no delete). Its `content_digest` is trustwork-digest-1 over `{ title, body, sourceRefs: [{ uri, sourceTime, observedAt, license }], eventTime, correctionOf, correctionNote, language }`, computed by the database (the tests compare it with `computeDigest`). After publication every change is a **correction**: a new published version with `correction_of`, a reader-visible note and an append-only `correction` row. **Retraction** keeps the title and an explanatory note visible and withholds the body.
- **Review and four eyes.** Editorial publications always need review: draft -> in_review by an editor, published by an editor holding `admin.publications.publish` who did not draft the version (`self_review`). Hubs may name formats whose personal or company publications are reviewed too (`reviewFormats`, default none). Retraction of an editorial piece needs `admin.publications.retract` (editor-in-chief in the test definitions).
- **Sources and times.** News names at least one source and the event time; the event time and the publication time are separate fields. A cited source carries its name, type (`industry_media`, `press_release`, `official_register`, …, `own_reporting`), licence label and the hub-console `AllowedUses` flags. Publishing is refused (`422`, `details.reason`) when a licence forbids the display (`licence_forbids_display`), the treatment (`licence_forbids_summary`, `_rewrite`, `_translation`) or assistant use of the text (`licence_forbids_model_use`); own reporting needs no third-party licence.
- **Moderation holds.** `ContentModerationTargets` implements ADM-001's `ModerationTargetPort` (wired in the composition root; other target kinds still reach ADM-001's recording fake). A hold or removal takes a publication or comment out of every public projection inside the staff command's transaction; the database checks that the moderation case supports the effect (open case with emergency hold, `content_removed` decision, `content_restored` or an overturning appeal). A hold whose case is decided without removal stops hiding the item. A held item keeps its slot in a released issue but shows no content.
- **Issues.** Numbered (unique per hub) and dated. Edition 1 is curated (`draft -> curated -> review`) and released by staff holding `admin.issues.release`; items pin exact published versions and are frozen with their revision for every role. A correction opens edition N+1 (a note is required), repins each item to its publication's current version (the curator may adjust) and, when released, writes the `correction` row; earlier editions stay readable (`?edition=`). Render artifacts record the released edition, format, hash and renderer version; a render completes once.
- **Digests.** Reference publications by home node, global id, version and licence; full text only for `cc_by` publications whose sources all allow syndication, otherwise headline and link. Cross-hub items are Proposed (federation); only local items are accepted today.
- **Walls** reference a publication (a pinned version or the current one), never copy it; a later correction or retraction shows on the wall.
- **Comments** are off unless the hub turns them on (`TRUSTWORK_CONTENT_COMMENTS=on` until HUB-001 configuration exists); signed-in people only; held and removed only through moderation cases.
- **No traction, no paywall.** No table, view or response carries readership, traffic, price, trial or paywall fields; public views are strict schemas (tested). Lists are ordered by time and id only.

The runtime role holds SELECT only on every content table (FORCE RLS: owner party, live editors and publications staff see working copies; issues and digests are staff-only until released). Every write is a `content_*` SECURITY DEFINER command; staff commands write the `admin_audit_event` row in the same transaction. Public reads are `content_public_*` functions, identical for every caller.

## Routes

All mutations: session, `X-Trustwork-Request`, `Idempotency-Key` (completed in the request transaction, BE-005). A publication command with `staff: { reason, reasonCode? }` acts as hub staff and needs a live elevation of the session. Errors use the contract envelope; database refusals are in `details.reason` (`not_authorised`, `self_grant`, `self_review`, `review_required`, `use_correction`, `issue_frozen`, a licence blocker, …) or `details.required` (`elevation`, `staff`).

| Route | Who | Result |
|---|---|---|
| `POST /v1/publications` | a person; a member with `company.publish`; editorial staff (`staff`) | Draft with version 1 and credits |
| `GET /v1/me/publications`, `GET /v1/publications/:id/manage` | owner party, editors, publications staff | Contract `Publication` list; working view (draft, published versions, corrections, editors, editions, moderation state) |
| `POST /v1/publications/:id/draft`, `/submit`, `/return`, `/publish` (`scheduledFor` for an embargo), `/corrections`, `/retract`, `/links` | rights as above | Lifecycle commands (`/links` replaces topics and entity links without touching the body; staff with `admin.publications.links.edit` may fix them) |
| `POST /v1/publications/:id/editors`, `/editors/:personId/revoke` | owner party (revoke also by the editor) | Editing rights |
| `POST /v1/publications/:id/editions`, `POST /v1/edition-links/:id/review` | editors of both publications; a reviewer other than the translator | Linked translations; machine assistance stays labelled until reviewed |
| `POST /v1/publications/:id/comments` | signed-in people, when comments are on | A comment |
| `POST /v1/walls`, `POST /v1/walls/:id/remove` | the person, or a member with `company.publish` for the company wall | Wall references |
| `GET /v1/publications`, `/v1/publications/:id`, `/v1/publications/:id/versions/:version`, `/v1/publications/:id/comments`, `/v1/walls/:kind/:id` | anyone | Public projections (feed: `format`, `topic`, keyset `before`/`beforeId`) |
| `GET /v1/magazine/issues` (`?year`), `/v1/magazine/issues/:number` (`?edition`), `/v1/magazine/digests/:id` | anyone | Archive, released editions (frozen `Issue` contract plus reader fields), released digests |
| `GET /v1/admin/content/publications` (`?status`), `GET/POST /v1/admin/content/issues`, `POST .../issues/:id/curate`, `/status`, `/release`, `/corrections`, `/renders`, `POST /v1/admin/content/renders/:id/result`, `GET/POST /v1/admin/content/digests`, `POST .../digests/:id/release` | staff behind `ElevationGuard`; console commands (contract version, idempotency key equal to the header, reason) | Editorial board, issue desk, render records, digests |

Scheduled publications are released by the worker entry point `content_publish_due(limit)` (granted to `trustwork_worker` only; wiring it into `apps/worker` is a follow-up). Outbox events carry identifiers only (`publication.*`, `issue.released`, `issue.corrected`, `issue.render_requested`, `digest.released`).

## Deviations and follow-ups

- Editing rights live in `publication_editor` instead of `object_participation` rows (see above); an integrator may migrate them once the foundation access functions know publications.
- Topics are exposed as taxonomy codes in the contract's `topicIds`.
- Agents cannot write publications yet (`403 access.mandate_scope`): no mandate kind covers publishing; drafting assistance is labelled through `assistantAssisted`.
- Not wired yet: the worker loop for `content_publish_due`, hub configuration for review formats and comments (HUB-001), sanctions enforcement for posting bans, the capability registry entries.

## CNT-003 reader and PDF delivery

Public reader schemas are shared unchanged from `packages/contracts/src/content-reader.ts`. The live DataPort consumes publications, version pins, archive and issue projections; workspace publication rows retain the caller session. `GET` and `HEAD /v1/magazine/issues/:number/pdf?edition=N` deliver only a durable local artifact whose captured public/licence projection still matches. The route returns 404 when unavailable and uses `private, no-store`; it never accepts a URL or fetches a remote asset. The local worker is opt-in with `CONTENT_PDF_RENDERER=local`. See [implementation boundaries](../../../../../docs/design/magazine/CNT-003-reader-boundaries.md) for provenance fields that remain proposed rather than inferred.

The owning database projections check the current linked SRC-001 source, item and activated import batch for each third-party reference. Missing, ambiguous or mismatched links withhold the publication; snapshot flags cannot widen current rights. Public detail, pinned versions, feeds, issue slots, walls, local digests and PDF share this gate. Headline-link versions have no public body. Nonconsenting co-author credits are omitted from detail and feed projections. Every public content route uses `private, no-store`. Source registry working views and private fields remain private.
